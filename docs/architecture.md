# Архитектура ИИ-Куратора (Техническая Документация)

Этот документ описывает внутреннее устройство ИИ-куратора, логику промптов, схему работы RAG-пайплайна и архитектуру базы данных. Он предназначен для проверяющих проект, а также для новых разработчиков, которые будут поддерживать или масштабировать систему.

---

## 1. Архитектура промптов (Prompt Architecture)

Системный промпт (`SYSTEM_PROMPT` в `src/agent.py`) спроектирован с учетом строгих ограничений и адаптивности. Он состоит из следующих логических блоков:

### Роль и задача
*   **Роль:** Senior ИИ-куратор и опытный наставник.
*   **Задача:** Направлять студентов, помогать усваивать материал, решать организационные вопросы.
*   **Метод:** Сократический диалог (задавать наводящие вопросы, а не давать готовые ответы).

### Тон и стиль общения
*   Эмпатичный, поддерживающий, профессиональный.
*   **Адаптивность:**
    *   *Для новичков:* простые аналогии, поощрение, избегание сложного жаргона.
    *   *Для продвинутых:* профессиональная терминология, ссылки на best practices (PEP8, SOLID).
*   **Структурированность:** использование списков и выделения жирным шрифтом для удобочитаемости.

### Строгие ограничения (Critical Rules)
1.  **Оценки:** НИКОГДА не выставляет, не обещает и не прогнозирует оценки.
2.  **Дедлайны:** НИКОГДА не сдвигает дедлайны (ссылается на grace period).
3.  **Код:** НИКОГДА не пишет готовый код за студента (только объяснение концепций и сниппеты-примеры).
4.  **Контекст:** Отвечает ТОЛЬКО на основе предоставленного контекста (RAG) и данных LMS.
5.  **Галлюцинации:** Если информации нет, честно признается в этом и направляет в поддержку.
6.  **Источники:** ВСЕГДА ссылается на источник информации (используя метаданные документа).

### Few-Shot Learning (Примеры)
В промпт встроены примеры правильных и неправильных ответов:
*   **Корректный пример 1 (Организационный):** Отказ в переносе дедлайна с объяснением правил grace period.
*   **Корректный пример 2 (Учебный):** Наводящая подсказка по сортировке словарей без написания итогового кода.
*   **Анти-пример (Некорректный ответ):** Демонстрация того, как ИИ *не должен* реагировать на просьбу поставить высокую оценку.

## 2. RAG-схема (Retrieval-Augmented Generation)

Система использует векторную базу данных для поиска релевантной информации и формирования контекста для LLM. Вся логика реализована в `src/rag.py`.

### 2.1. Индексация (Indexing)
*   **Источники:** Поддерживаются форматы `.json` (FAQ, структура курса), `.pdf`, `.docx`, `.txt`.
*   **Метаданные:** При загрузке каждому документу присваиваются метаданные:
    *   `source` (имя файла)
    *   `module` (учебный модуль)
    *   `topic` (тема)
    *   `type` (тип документа: faq, lecture, manual)
*   **Чанкинг:** Документы разбиваются на части с помощью `RecursiveCharacterTextSplitter` (chunk_size=1000, chunk_overlap=200) для обеспечения точного семантического поиска.
*   **Векторизация:** Используется модель `text-embedding-3-small` от OpenAI. Векторы сохраняются в локальную БД **ChromaDB**.

### 2.2. Поиск (Retrieval)
*   При поступлении запроса от студента, система преобразует запрос в вектор и ищет `k=4` наиболее релевантных фрагментов в ChromaDB.
*   Найденные документы передаются в LLM в качестве контекста.

### 2.3. Формирование контекста (Generation)
*   **Интеграция метаданных:** В LangChain настроен кастомный `document_prompt`, который передает метаданные (источник, модуль, тема) вместе с текстом документа прямо в промпт.
*   Это позволяет LLM выполнять правило №6 из системного промпта — **ссылаться на конкретный источник** при ответе.

## 3. Архитектура базы данных (SQLite)

Для хранения данных используется реляционная база данных SQLite (`src/db.py`). Структура включает следующие основные таблицы:

1.  **students:** Хранит профили студентов (id, имя, курс, уровень подготовки, прогресс, логин, хэшированный пароль).
2.  **chat_messages:** История диалогов между студентом и ИИ. Сохраняет роль (user/assistant), текст сообщения и JSON с метаданными контекста (для аналитики и отображения источников).
3.  **escalations:** Тикеты поддержки. Создаются, когда ИИ не может ответить на вопрос или студент просит перевести диалог на человека.
4.  **support_messages:** Сообщения внутри конкретного тикета эскалации (чат между администратором и студентом).
5.  **feedback:** Оценки и отзывы по выполненным домашним заданиям.

## 4. Панель Администратора и Аналитика

Интерфейс администратора представляет собой полноценную мини-LMS систему со следующими вкладками и возможностями:

*   **💬 Чат (Симуляция):** Админ может выбрать любого студента из выпадающего списка и вести диалог с ИИ от его лица. ИИ автоматически подстроит тон под уровень выбранного студента.
*   **👥 Студенты:** Таблица со списком всех зарегистрированных студентов, их курсами, уровнем подготовки и текущим прогрессом (%).
*   **📁 База знаний:** Отображение всех файлов, загруженных в `data/kb/`, с возможностью запустить процесс переиндексации векторной базы (ChromaDB) одной кнопкой.
*   **📊 Аналитика:** 
    *   **Сбор данных:** Все запросы логируются в CSV-файл (`data/analytics/query_logs.csv`).
    *   **Дашборд:** Вывод метрик (общее число запросов) и круговой диаграммы распределения вопросов по темам.
    *   **Логи чатов:** Просмотр полной истории переписки любого студента с ИИ для контроля качества (QA).
*   **📚 Программа:** Отображение структуры курса и дедлайнов (подтягивается из `schedule.json`).
*   **📥 Проверка ДЗ:** Интерфейс проверки домашних заданий. Админ видит сданные файлы, может выставить оценку (score), написать текстовый фидбек и начислить проценты прогресса, которые сразу отразятся в профиле студента.
*   **📨 Запросы (Эскалации):** Встроенный Helpdesk. Если студент нажал "Позвать человека", здесь создается тикет. Админ видит историю переписки с ИИ, может ответить студенту напрямую (двусторонний чат) и пометить проблему как решенную (Resolve). Система также отслеживает счетчик непрочитанных сообщений.

## 5. Инструкция по обновлению базы знаний

Для добавления новых материалов в базу знаний ИИ-куратора:

1.  Поместите новые файлы (PDF, DOCX, TXT) или обновите JSON-файлы в директории `data/kb/`.
2.  Убедитесь, что в JSON-файлах корректно заполнены поля `topic` и `module` для точной работы метаданных.
3.  Запустите скрипт переиндексации:
    ```bash
    python -m src.rag
    ```
4.  Скрипт очистит старую коллекцию в ChromaDB и создаст новую с актуальными документами.
5.  Перезапустите основное приложение Streamlit.

## 6. API-имитация (Заглушка для интеграции с LMS)

Поскольку проект является учебным, интеграция с реальной LMS (Learning Management System) имитируется через локальные файлы:
*   **Расписание и структура курса:** Хранятся в `data/lms/schedule.json`.
*   **Профили студентов:** Загружаются из `data/lms/students.json` при инициализации БД.
*   В будущем эти файлы могут быть заменены на реальные HTTP-запросы к API образовательной платформы (например, Moodle или Canvas).
